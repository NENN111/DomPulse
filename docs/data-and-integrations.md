# Данные и интеграции

SQLite хранит дома, пользователей, заявки, события, привязки MAX, состояния диалогов, входящие обновления, outbox, SLA-уведомления и общие инциденты. `ticket_attachments` подготовлена для метаданных вложений; бинарные файлы не сохраняются. При открытии заявки оператору фотографии передаются как вложения MAX.

Реальная интеграция: MAX Bot API по HTTPS, webhook или long polling. Тесты используют `httpx.MockTransport` только как автоматическую проверку контракта. Интеграций с ГИС ЖКХ и внутренними системами УК нет. Seed-данные полностью синтетические.

MAX передаёт фотографии в `Message.body.attachments` с типом `image`. Бот принимает фото на любом этапе создания заявки и сохраняет идентификатор и метаданные в `ticket_attachments`. Бинарный файл в базу не записывается.
## Госуслуги и адрес регистрации

ДомПульс не обращается к ЕСИА без официального подключения. Настраиваемый Госуслуги-bridge выполняет авторизацию пользователя, получает разрешённые адресные сведения и отправляет в `/api/integrations/gosuslugi/residency` только идентификатор субъекта и домовую часть постоянной/временной регистрации. Callback подписывается HMAC-SHA256; одноразовый `state` действует 15 минут и защищён от повторного использования.

Активная временная регистрация имеет приоритет при выборе текущего дома, но все совпавшие действующие регистрации добавляются в раздел «Мои дома». Автоматическая привязка выполняется только к уже известным домам по идентификатору ФИАС или точному нормализованному адресу. Полный адрес квартиры, токены ЕСИА и исходный идентификатор гражданина не сохраняются. При отсутствии bridge или совпадения пользователь вводит адрес вручную и подтверждает каждый дом одноразовым кодом УК. Геокодер проверяет адрес и округ, но сам по себе не даёт доступ к дому.

Официальная основа интеграции: [методические рекомендации по использованию ЕСИА](https://sc.digital.gov.ru/documents/-/document_library/03jzkn2sfJTq/view_file/3874188).
