# Данные и интеграции

SQLite хранит дома, пользователей, заявки, события, привязки MAX, состояния диалогов, входящие обновления, outbox, SLA-уведомления и общие инциденты. `ticket_attachments` подготовлена для метаданных вложений; бинарные файлы не сохраняются.

Реальная интеграция: MAX Bot API по HTTPS, webhook или long polling. Тесты используют `httpx.MockTransport` только как автоматическую проверку контракта. Интеграций с ГИС ЖКХ и внутренними системами УК нет. Seed-данные полностью синтетические.

Официальная документация подтверждает `Message.body.attachments` и тип `image`, но текущий входящий контракт идентификаторов изображения не зафиксирован в проекте достаточно надёжно. Поэтому приём фото выключен до интеграционного теста с реальным событием MAX.
## Госуслуги и адрес регистрации

ДомПульс не обращается к ЕСИА без официального подключения. Настраиваемый Госуслуги-bridge выполняет авторизацию пользователя, получает разрешённые адресные сведения и отправляет в `/api/integrations/gosuslugi/residency` только идентификатор субъекта и домовую часть постоянной/временной регистрации. Callback подписывается HMAC-SHA256; одноразовый `state` действует 15 минут и защищён от повторного использования.

Активная временная регистрация имеет приоритет перед постоянной. Автоматическая привязка выполняется только к уже известному дому по идентификатору ФИАС или точному нормализованному адресу. Полный адрес квартиры, токены ЕСИА и исходный идентификатор гражданина не сохраняются. При отсутствии bridge или совпадения пользователь вводит адрес вручную и подтверждает его одноразовым кодом УК.

Официальная основа интеграции: [методические рекомендации по использованию ЕСИА](https://sc.digital.gov.ru/documents/-/document_library/03jzkn2sfJTq/view_file/3874188).
